# P2 + P3 — Who's Who Data Extraction & Interactive Network Page

**Branch:** `feat/p2-p3-network`
**Scope:** Refactor `/whos-who` to consume a shared typed data module, expand the roster from 30 to ~80 figures, then build the interactive `/network` page on the same data source.

The two packages share the `content/whos-who/figures.ts` data file as single source of truth. Shipping together prevents schema drift.

---

## PART A — DATA MODEL

Create `content/whos-who/figures.ts` and `content/whos-who/connections.ts`. The `/whos-who` page becomes a thin renderer over figures. The `/network` page is a client component visualizing both.

### Figure schema (TypeScript types — design as you see fit, but cover these fields)

Each figure has:

- `id` — kebab-case slug, stable, used by edges (e.g., `david-grusch`)
- `name` — display name
- `category` — exactly one of: `government-military`, `intelligence-community`, `legislator`, `scientist-academic`, `witness-experiencer`, `journalist-investigator`
- `affiliations` — array of organization/program/event strings; these drive the compound-node grouping in P3. Use canonical names so identical strings cluster (e.g., always `"Sol Foundation"`, not `"the Sol Foundation"`)
- `role` — short narrative phrase (≤120 chars) describing role in the disclosure narrative
- `bio` — the existing-style 2–4 sentence calibrated paragraph for the `/whos-who` page
- `stakeholderFlags` — array; zero or more of: `defense-contractor`, `energy-industry`, `legislative-blocker`, `disclosure-advocate`, `intel-community`, `whistleblower`, `experiencer`, `deceased`, `missing`, `contested-status`
- `status` — `active` | `deceased` | `missing` | `retired` (display-only, supplements flags)
- `dateOfEvent` — optional ISO string for deaths/disappearances
- `calibrationNote` — optional; used for contested figures where evidence cuts in multiple directions (see "Calibration discipline" below). When present, the network and Who's Who pages must surface it visibly.
- `cites` — array of inline citation strings or URLs; light, just enough to evidence the bio

### Connection schema

Each connection edge has:

- `source` — figure id
- `target` — figure id
- `type` — exactly one of: `co-authored`, `co-founded`, `co-testified`, `investigated-together`, `public-dispute`, `mentor-mentee`, `funded`
- `note` — short string explaining the relationship (≤80 chars)
- `year` — optional 4-digit year or year range

Both files export typed arrays. Keep import-friendly: `import { figures } from "@/content/whos-who/figures"`.

---

## PART B — CALIBRATION DISCIPLINE (READ THIS BEFORE WRITING BIOS)

The site's foreword commits to distinguishing established fact, strong evidence, credible testimony, contested evidence, and speculative frameworks. Every new figure must respect that bar.

For contested entries — particularly the "missing scientists" cohort — write the bio in this voice:

> **DO:** State what is documented (the death/disappearance, the official cause of record, the person's expertise). State that the case has been **cited within a broader narrative** of targeted attrition. State the strongest counter-position on the public record (e.g., Avi Loeb's *"We have a Missing Science problem, not a Missing Scientists problem"* essay; Trump's own statement that federal briefings show no meaningful link; the Wilcock family's statement attributing his death to depression and financial debt).

> **DO NOT:** State as fact that any of these individuals were neutralized by state actors. The site is not a vector for unsourced assertions, regardless of how compelling the narrative.

When in doubt: tag `contested-status` in stakeholderFlags and put the calibration in `calibrationNote`. The Who's Who page must render the calibrationNote inline. The Network page must surface it in the hover-card with a distinct visual treatment (italic, smaller, muted color).

### D.2 — Graph: Cytoscape.js with compound nodes

Implement as a client component (`"use client"`) dynamically imported with `ssr: false`. Use `react-cytoscapejs` with the `cytoscape-cose-bilkent` layout extension registered at module load.

**Compound parent grouping:** Each unique affiliation string in the figures data becomes a compound parent node. Member figures are children of the parent. A figure with multiple affiliations is a child of one *primary* parent (first item in the affiliations array) and connected via edges to its other affiliations represented as ghost-edge connections to those parents. The cose-bilkent layout handles compound layout well; tune `nestingFactor`, `idealEdgeLength`, and `nodeRepulsion` for legibility.

**Visual encoding:**

| Property | Encoding |
|---|---|
| Node fill color | Category (6 colors — pick from the existing site palette: accent-blue family for primary categories, use varied saturations/hues that work on the kinematic dark background) |
| Node border ring | Stakeholder flag — multiple flags = multiple concentric rings or a striped border. `legislative-blocker` → red ring. `defense-contractor` → bronze ring. `energy-industry` → amber ring. `whistleblower` → emerald ring. `contested-status` → dashed gray ring. `deceased` → black ring with crosshatch. `missing` → dashed black ring. |
| Node size | Constant for v1; could scale by degree centrality in v2 — leave as future enhancement |
| Node label | Last name only at default zoom; full name on hover/zoom |
| Edge color | Type — `co-authored` solid blue, `co-founded` solid violet, `co-testified` dashed cyan, `investigated-together` solid teal, `public-dispute` solid red, `mentor-mentee` dotted gold, `funded` dashed orange |
| Edge thickness | Constant 1.5px |
| Compound parent | Translucent fill with the parent name in small caps label at top; no fill on hover |

All colors must be themed via CSS custom properties in `globals.css` so the palette is a single source of truth.

**Interactions:**

- Hover over a node → show hover-card overlay (HTML div positioned via Cytoscape's `renderedPosition` of the node, with viewport edge collision detection). Card contains: name, category, affiliations (as chips), role, full bio, stakeholder flags (as colored chips), calibrationNote (italicized, smaller, distinct) if present, cites (linked).
- Click node → pin hover-card open; click outside or press Esc to close
- Hover over edge → small tooltip with edge type + note + year
- Click compound parent → fade non-member nodes to 20% opacity; click background to reset
- Search input above graph: filter nodes by name match; non-matches fade to 20% opacity
- Category legend in a small panel beside the graph (or top-right corner overlay), toggleable: clicking a category dims/restores its nodes
- Stakeholder legend similarly
- Zoom + pan via Cytoscape defaults; add a "Reset view" button

**Performance:** ~80 nodes + ~150 edges + ~20 compound parents is well within Cytoscape's comfortable range. Use `headless: false`, `wheelSensitivity: 0.2`, and disable node-dragging once the layout settles (`autoungrabify: true` after first `layoutstop`).

**Mobile fallback:** On viewports below 768px, render a compact view: vertical list grouped by compound parent (effectively a structured Who's Who), with a banner explaining the interactive graph requires a larger screen. Mobile users still get full data, just non-graph rendered.
